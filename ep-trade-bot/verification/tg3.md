## 1. What was built

| Piece | Where | What it does |
| --- | --- | --- |
| Broker plugin contract | `Core/Brokers/BrokerContracts.cs` | `IBrokerPlugin` plus capability interfaces (orders, portfolio, funds, quotes and depth; GTT, margin, history, symbol master, streaming and login are declared as capabilities and arrive with the plugins that need them). A missing capability is a plain refusal. |
| Plugin discovery | `Infrastructure/Brokers/BrokerInfrastructure.cs` | Every class marked `[BrokerPlugin]` is found at startup; only those named in `Brokers:Enabled` (OpenAlgo's VALID_BROKERS) are offered. |
| Keys read when called | `BrokerSessionFactory` | Each call decrypts the account's token and reads the broker's keys from configuration at that moment. Nothing is cached in a static. |
| Token encryption | `Infrastructure/Security/Secrets.cs` | AES-256-GCM, key derived from `Security:AppKey` by HKDF. Each ciphertext is bound to its account and field, so a token copied to another account does not decrypt there. |
| Per-account API keys | `AccountApiKey`, `ApiKeyService` | An /api/v1 key belongs to one account; the key a request carries is the account it trades. Stored as HMAC-SHA256 under `Security:ApiKeyPepper`; shown once; revocable. |
| Zerodha plugin | `Infrastructure/Brokers/Zerodha/ZerodhaPlugin.cs` | Port of broker/zerodha: place (with order-book recovery by tag when the reply is lost), modify, cancel, order book, trade book, positions, holdings, funds, quotes, depth. |
| Shared book formatting | `Core/Brokers/BookFormatting.cs` | OpenAlgo's service-layer formatting, including Python's own rounding (`round(2.675, 2)` is 2.67). |
| /api/v1 service | `Infrastructure/OpenAlgoApi/OpenAlgoApiService.cs`, `Api/Endpoints/OpenAlgoV1Endpoints.cs` | 18 OpenAlgo paths (section 3). PAPER accounts answer from the sandbox with `"mode": "analyze"`; LIVE accounts from their broker. Every order goes through the order dispatcher (guard, risk, audit); modify, cancel, cancel-all and close-all are guard-checked first. API key in the body or the `X-API-KEY` header. |
| Live order router | `Infrastructure/Brokers/BrokerLiveOrderRouter.cs` | Replaces the TG2 stand-in. LIVE exposure for the risk check comes from the broker's positions; a position book that cannot be read still refuses the order. |
| Market-data bus | `Infrastructure/Streaming/MarketDataBus.cs` | NetMQ SUB socket, the only binder of `Streaming:BusPort`, bound during startup; publishers connect. Each tick prices the quote book (risk checks, sandbox fills) and is fanned out. |
| WebSocket proxy | `Api/Streaming/WebSocketProxy.cs` | OpenAlgo's client protocol on port 8765 (any path) and `/ws`: authenticate, subscribe, unsubscribe, unsubscribe_all, ping, get_broker_info, subscribe_orders. |
| Sandbox fills from ticks | `SandboxTickMatcher` | Resting sandbox orders fill as ticks arrive; a burst of ticks for one instrument costs one match. |
| Order updates | `OrderEvents`, `Api/Streaming/OrdersHub.cs` | Every dispatched order (accepted, refused, failed) goes to SignalR (`/hubs/orders`) and to WebSocket order subscribers. |
| Credential endpoints | `Api/Endpoints/CredentialEndpoints.cs` | Issue, list, revoke API keys; store or clear a LIVE account's broker token (admin token until login lands in TG5). |

New migration `ApiKeysAndBrokerSymbols` adds `core.account_api_keys` and a
`broker` column on `core.symtoken` (OpenAlgo held one broker's master contract
at a time; accounts here can be on different brokers). It has no `Sql()` call.

## 6. Deliberate differences from OpenAlgo

- **Unknown symbol.** OpenAlgo sends `tradingsymbol: "None"` to Kite when a symbol is not in the master contract (recorded in fixture `placeorder_unknown_symbol`). EP Trade bot refuses before sending anything.
- **API key in the header.** OpenAlgo's /funds schema requires `apikey` in the body, so its header is refused there (fixture `auth_header_key`). EP Trade bot accepts `X-API-KEY` on every endpoint, as the brief asks.
- **Analyzer mode is per account.** OpenAlgo has one platform-wide switch. Here the API key names the account and the account is PAPER or LIVE, so `/analyzer` reports the account's mode and `/analyzer/toggle` explains this instead of switching. A platform-wide switch that diverts live exits to the sandbox is exactly what the CLAUDE.md invariant warns about.
- **Guard and risk on API orders.** OpenAlgo has no per-account risk limits on /api/v1. Here API orders pass the environment guard and the account limits like every other order; a refusal is a 400 (403 for the environment lock).
- **Modify on a sandbox order** is refused with a plain message (cancel and place again); the sandbox has no modify yet.
- **No server-side tick throttling.** The plan said the proxy throttles. OpenAlgo removed that (it dropped ticks in bursts); the port follows OpenAlgo: every tick is forwarded, and a slow client's queue is bounded and drops its oldest messages.

## 8. Other limits

- LIVE daily loss for the risk check is the sum of the broker's position P&L, which for Kite's net positions includes carried-forward positions, not only today's.
- PAPER books are built from the sandbox tables in OpenAlgo's analyze-mode shape; they are tested for behaviour, not recorded against Python's sandbox (whose ids and timestamps differ by design).
- One test database was left behind by mutation C16, where the mutated host started and was never disposed; it was dropped by hand. A normal run leaves none (checked).
